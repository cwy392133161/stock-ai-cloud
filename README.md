# A 股 + 港股 AI 选股榜（免费云端版）

每天工作日北京时间 17:10 自动跑一次：GitHub Actions 用 AKShare 免费接口拉取
A 股 + 港股行情，按趋势 / 活跃度 / 估值 / 规模多因子打分，各市场取 Top 20，
生成中文网页，通过 GitHub Pages 发布，iPhone 用 Safari 就能看。

> ⚠️ 这是**规则化多因子评分**，不是大语言模型分析；结果仅供学习参考，
> **不构成任何投资建议**。股市有风险，入市需谨慎。

## 部署步骤（5 步）

### 第 1 步：创建 GitHub 仓库

打开 https://github.com/new ，仓库名填 `stock-ai-cloud`，选 **Public**（免费
Pages 要求公开仓库；选股结果将公开可见），点 **Create repository**。

### 第 2 步：上传项目文件

把本项目所有文件上传到仓库，保留文件夹结构：

```
stock-ai-cloud/
├── picker.py                        选股脚本
├── ai_report.py                     AI 深度分析（可选，需 DeepSeek 密钥）
├── requirements.txt                 依赖（akshare）
├── README.md                        本说明
├── docs/
│   ├── index.html                   榜单网页（首次运行后自动覆盖）
│   ├── data.json                    榜单数据（供 AI 报告读取）
│   └── ai.html                      AI 深度分析页（开启后自动生成）
└── .github/
    └── workflows/
        └── daily.yml                每天 17:10 自动运行
```

网页上传：仓库页面点 **Add file → Upload files**，把文件拖进去，点
**Commit changes**。注意 `.github` 是隐藏文件夹，上传时要把整个
`.github/workflows/daily.yml` 路径保留好。

### 第 3 步：启用 GitHub Pages

仓库 **Settings → Pages → Build and deployment**，Source 选
**Deploy from a branch**，Branch 选 `main`，文件夹选 `/docs`，点 Save。

### 第 4 步：首次手动运行

仓库 **Actions → Daily stock screening and Pages → Run workflow**，
等几分钟。出现绿色 ✅ 表示成功；红色 ❌ 点进去看失败步骤的日志。

### 第 5 步：iPhone 查看

成功后访问：`https://你的GitHub用户名.github.io/stock-ai-cloud/`

iPhone Safari 打开后点 **分享 → 添加到主屏幕**，以后像 App 一样打开。

## 选股逻辑

- 过滤：ST / 退市、流通市值过小（A 股 < 20 亿、港股 < 20 亿港币）、
  当日成交额过小（A 股 < 5000 万、港股 < 1000 万港币）、停牌无价的股票
- 打分：趋势 40% / 活跃度 25% / 估值 20% / 规模 15%，用百分位排名，
  各市场分别取前 20 名；港股与 A 股用同一套打分
- 数据源：直调东方财富免费行情接口（慢速分页、多台服务器轮换），
  失败时依次兜底 AKShare 东财源、新浪源；免费接口对云端共享 IP
  偶有限流，单次运行失败属于正常现象，重跑通常能恢复
- 每只入选股票附中文入选原因和风险提示（如追高、情绪过热、估值偏高）

## AI 研究模块：现行架构与边界

规则化选股榜仍然独立运作：A 股 Top20 + 港股 Top20，趋势40% / 活跃25% /
估值20% / 规模15%，每天各市场前5只进入 DeepSeek 研究，共10份。

**研究输入**
- 行情结构化快照：价格、评分、60日/YTD走势、动态PE/PB；A股在全市场流动性过滤后
  的同一行情快照按供应商行业/板块分组，达到样本门槛才输出PE/PB中位数；
  港股不臆造无可靠分类的同行样本。
- 多期财务：复用当前 AKShare 财务接口已取得的历史报告期，披露/修订日期必须
  不晚于行情快照；仅同季、同期间跨年对照，A股原币核实后保留累计营收、
  归母净利润与经营现金流（现金流历史复用已经获取的报表）；港股原币历史金额
  未确认时不输出，百分比和比率按实际期间展示。
  每条现金流单独保留自身报告期、币种、金额和 `NOTICE_DATE` / `UPDATE_DATE` 来源，
  不借用主要指标的披露日期；全部已提供日期必须有效且介于报告期末与行情快照之间，
  以较晚日期作为保守可用时点。缺少自身日期、修订晚于快照或口径不唯一时不采用。
  这些是第三方日期字段校验，不等同于已审计的历史时点数据库。年度对照仅比较相邻年度
  同报告季，缺少上年同期或其中某个指标时，不用更早年份替代。
- 巨潮资讯 / 港交所披露易：报告期定向搜索相应财报，最多读取2份重要PDF，
  摘录含页码、表头、币种单位、期间上下文；只保留页面可定位的公开披露链接。
- 交易行业横截面：在相同快照中形成PE/PB中位数，只有超过最低样本量和覆盖率时才提供统计，
  不构成“合理估值”或行业领先结论。
- 同行业财务对照：A股存储同供应商行业标签、流通市值约1/3～3倍的同行候选，
  报告生成阶段遍历符合条件的全部同行候选（复用缓存，不设置项目内API调用次数上限），核对**同一个报告期和披露截止时间**的
  营收同比、归母净利润同比、ROE与负债率；少于3家真实可比同行时不生成中位数。
  不把便利样本当成机构级可比公司模型；港股没有可靠同业分类/币种时不生成同行财务比较。
- 研究底稿：趋势、财务变化、行业估值差异（如果样本足够）、逆向证据、
  下一期指标跟踪、假设情景与资料覆盖级别，并将程序金额核对和AI推论分开。
- 程序审核：AI必须输出四章节JSON。若公司事实要成为可展示的“已披露主张”，
  则其完整句子必须逐字出现在同一来源的PDF短引之中，短引还必须逐字存在于该PDF页码摘录；
  不允许AI换词改写后直接标成原文事实。复杂因果推论仍不能靠程序完全审核，
  需要独立人工复核；没有事实证据时只显示可确定的数据分析。
- 研究差异化：以各公司的营收和归母利润方向、现金流、ROE、杠杆及资料缺口生成研究重点；
  对10只股票的AI四章节正文做相似度检查，极度雷同者不发布解释性研判，
  而显示事实和研究限制。不同语言表达仍可能具有同一观点，真实效果须审查线上报告。

**明确限制**：逐字匹配能证明“摘录引用位置与主张文本一致”，但不能独立审核全部
经济含义，也无法自动验证管理层的真实性；小规模同行财务接口可能失败并明确显示样本不足。
AI内容并非人工撰写的机构投资意见，需在实际生成后逐篇核验来源和观点。这个系统不提供
已审计的完整财务数据库、可审计的多行业盈利预测、
管理层访谈、历史PE分位、真实DCF估值或投资组合回测。缺少这些信息时不能
宣传为已经具备机构级证券研究能力，也不提供买卖指令或收益保证。

**测试与运行**：`.github/workflows/research-tests.yml` 仅运行语法、离线
单元测试，**不调用DeepSeek、不执行实时选股**；
`.github/workflows/daily.yml` 才负责正式生成更新榜单和AI报告。
日常失败时需核对 `docs/data.json` 与 `docs/ai.html` 的时间戳是否一致。

### AI研判全部显示“未通过门槛”时

最新研究采用分级发布：来源与时间核验失败、严重包含无依据事实、JSON不完整时，
仍只显示程序事实；无逐字匹配PDF公司事实，但有同快照财务证据、可证伪的条件性分析时，
展示“条件性研究（原文事实证据不足）”；只有直接主张与官方PDF摘录逐字匹配并且
四段有效时，才标注包含官方原文支持的研究。不能把条件性结论当成公司已披露事实。

之前的 `docs/ai.html` 是已渲染网页，不存储原始DeepSeek模型JSON；更新研究代码
不会自动变成新文章。可在 Actions → Daily stock screening and Pages 中运行
`report_only=true`，沿用现有行情快照重新生成10篇报告。此操作调用API，会产生费用。

### 数据真实性与发布安全（更新）

- **单一截止时点**：以选股快照的实际日期为唯一研究时点；财报期间不能
  代替披露日期。缺少报告披露或修订时点的历史数据，不宣称当时可获得。
- **公告索引**：巨潮资讯按总条目数持续分页、港交所按日期窗口递归拆分，
  不设置项目内固定查询次数上限；接口返回重复页面或单日数据超出服务商最大返回量时，
  明确标记“可能未查全”，禁止将部分结果描述成完整公告库。
- **证据审核**：DeepSeek 必须返回四章节结构化 JSON；公司公告事实单独展示
  逐字匹配官方 PDF 摘录的原文短引及页码。未知引用、拼凑引文或缺少表头、
  单位、期间的金额摘录不得作为已核对证据。逐字校验并不等于语义蕴含
  校验，更不等于审计，重大研究结论仍需人工回读全文。
- **硬发布门槛**：快照时点、财务数据、结构化研究文本和至少一段可逐字
  核对的官方原文均需合格，才展示模型的解释性研究；否则保留程序事实
  和公告链接，并明确提示“AI研判未通过发布门槛”。
- **新旧报告不混淆**：\`publish_guard.py\` 在选股和 AI 步骤后运行。AI 成功、
  部分通过、仅事实摘要、失败、关闭、旧研究等状态都会写入
  \`docs/ai-status.json\`，在**首页和报告页同时标注**。
  正式 AI 失败不会阻断规则选股榜发布，但旧报告不会被标成新报告。
- **同业估值局限**：至少20只A股同一行情行业标签样本，动态PE/PB
  至少12只有效报价且覆盖率不低于60%才显示中位数；动态PE不等于TTM，
  样本横截面不是合理价值，也不代表业绩增速或竞争力。
- **内容简化**：四章节 AI 研判优先展示，原始财务、财报页码、
  多年同期对照和三种**基于现有财务事实的**经营假设可展开核对。
- **验证**：\`.github/workflows/research-tests.yml\` 只执行语法与离线测试；
  新报告必须在正式选股或手动 \`report_only\` 中生成。单元测试通过不代表
  官方公告接口当日可用，也不保证 DeepSeek 分析结论正确。

### 开启方法（4 项配置）

去仓库 **Settings → Secrets and variables → Actions**：

| 配置项 | 放在哪里 | 值 |
| --- | --- | --- |
| `AI_API_KEY` | Secrets（点 New repository secret） | 去 platform.deepseek.com 注册并充值后创建的 API 密钥 |
| `AI_ENABLED` | Variables（点 New repository variable） | `true` |
| `AI_BASE_URL` | Variables | `https://api.deepseek.com` |
| `AI_MODEL` | Variables | `deepseek-flash`（最便宜，约 ¥0.033 / 百万 Tokens 起） |

配好后去 **Actions → Daily stock screening and Pages → Run workflow**
手动跑一次，等几分钟，打开榜单页看链接，或直接访问
`https://你的GitHub用户名.github.io/stock-ai-cloud/ai.html`。

费用取决于所用模型、输入财报篇幅和实际 token 用量。每天仍研究A股5只+
港股5只（共10份报告，属于研究范围，不是API调用额度）；每只股票的DeepSeek
请求不再限制为固定2次，而是在研究执行时间窗口内对空输出、HTTP 429、临时
服务错误进行退避重试。同行财务、巨潮资讯分页及港交所公告检索不设置项目内
请求次数上限，数据范围有限且请求结果缓存复用。**API真实调用量和Token费用
可能明显增加**，请自行设置服务商账户预算或消费提醒。服务商限流、第三方返回
条数、网络超时和GitHub Actions执行时间限制依然生效；不能通过改代码取消。
关闭：把 `AI_ENABLED` 改回 `false` 再跑一次工作流即可；
关闭后榜单不受影响，旧的 ai.html 会保留到下一次运行。

## 常见问题

**定时任务没跑 / 延迟？**
GitHub 官方说明：定时工作流可能延迟；公开仓库长期没有活动时，定时
工作流可能被停用。本项目每天成功运行都会提交一次结果，本身就是活动，
一般不会被停用。节假日无行情时，页面会保留上一次的结果，请看页面上的
更新时间。

**运行失败，日志说接口限流 / 拉不到数据？**
免费行情接口（东方财富 / 新浪）会对云端共享 IP 限流或拦截。脚本已内置
重试（东方财富失败后等待 120 秒、300 秒再试，仍失败改试新浪源）。
如果还是失败，等一段时间后在 Actions 页面点 **Re-run jobs** 重新跑一次。
当天多次失败是正常的，第二天通常会恢复。

**页面显示的还是旧结果？**
先看页面顶部的更新时间。工作日 17:10 运行，若失败则保留上一次结果，
属于正常现象。
